# 导出与迭代

默认 H.264 / AAC MP4、1080×1920、30fps，附可编辑工程和素材分类说明。根据当前工具与设备选择导出方式，不写死旧项目目录、CLI 路径或缓存哈希。

保存镜头清单：源文件、源片起点、使用时长、成片起点、活动说明和声音取舍。时长修改后同步后续章节、音轨、配乐淡出、字幕和来源表。反馈时间点先在当前版本定位。

模板获认可后只改相关内容。纯声音修改可重做音轨、复用原视频；片尾修改可只重渲染相关部分，但最终视觉、时序必须与完整渲染一致。

## HyperFrames 的实际经验

运行当前 CLI 的 lint、runtime / layout / contrast 检查，查看关键帧。辅助渲染入口放独立临时工程或在正式检查前移走；正式工程只保留一个根入口，避免重复音频和 multiple_root_compositions。

低内存设备长片截图捕获卡顿时，可改用可续传分段方式，避免整片反复重跑。已验证示例，执行前核对当前 CLI 支持情况：

```bash
HF_SEGMENTED_CAPTURE=true HF_SEGMENT_FRAMES=300 HF_SEGMENT_BROWSER_RECYCLE=2 \
  hyperframes render --workers 1 --resume --keep-segments --quality delivery
```

支持的本机硬件编码可加速。交付包排除 node_modules、缓存和临时入口。部分混音处理器成功后清理临时目录，最终音轨须放在临时目录之外，确认确实存在且有声音。

## 拼接检查

相同帧率的 MP4 仍可能 time base 不同，直接流复制拼接会导致片尾时长错误和音画错位。核对编码参数、尺寸、帧率和 time base；必要时无损重封装统一时间基：

```bash
ffmpeg -i tail.mp4 -map 0:v:0 -c:v copy -video_track_timescale 90000 \
  -an tail-normalized.mp4
```

再拼接并混入完整新音轨。验证视频轨时长，不只看容器或音轨时长。

## 实际成片

- 宽高、帧率、帧数、视频轨时长匹配；声音覆盖完整视频，没有空文件。
- 查看章节、横屏留白、修改位置、拼接前后及片尾的实际 MP4 帧。
- 检查指定消音位置和儿童祝福、吹蜡烛，确认重要原声保留。转写可辅助核对，不能据此判断身份或保证混合人声拆分成功。
- 实际视频通过后再宣布完成，提供最终成片。源文件不改动。
